### 动手前的现况
仓库**没有 README**（`ls README*` 为空）。所以这是从零新写，不是改。

### 原则：所有数字都实测，不凭印象
写简介最容易翻车的地方是数据写错（环数、条数、档位、包体）。
本轮的取舍是**每一项都从源码取**：

| 事实 | 取值方式 | 结果 |
|---|---|---|
| 六环名称 | `grep "name: '"` 于 `Luopan3D.tsx` 的 `ARMILLARY_RINGS` | 先天八卦天运环 / 五行生克环 / 道历二十四节气天环 / 二十四山神位天环 / 二十八宿四象天纬环 / 周天赤道道历天铭环 |
| 二十四山 / 二十八宿 / 八卦 / 五行 / 节气 | **用 bun 直接 import 模块数 `.length`** | 24 / 28 / 8 / 5 / 24 |
| 百科条目 | `import { MOUNTAIN_WISDOM_MAP }` 后 `Object.keys().length` | **24**（每篇含 ancientPoem / classicQuote / astronomyOrigin / fengshuiSignificance / cultivationVirtue 等 11 字段） |
| 转速档 | `SPEED_PRESETS` | 0.25x / 1.0x / 3.0x（标签：悠缓 / 沉稳 / 灵动）|
| 基准转速 / 单步 | `ROTATION_DEG_PER_SEC` / `SINGLE_STEP_DEG` | 均 **1.0** |
| 视角俯角 | `phi: 0.72` 换算 | **41.3°**（README 里写 41°）|
| 包体 | `wc -c dist/assets/*.js` + `gzip -c` | **957 KB / gzip 257 KB** |

**踩过的坑**：一开始用正则数 `MOUNTAINS_24` 得到 13、`MANSIONS_28` 得到 24 —— 全是错的
（对象字面量的 `id:` 行并不唯一对应条目）。
**正解：直接 `bun run` 一个临时 .ts 去 import 真实模块取 `.length`**，
比正则可靠得多。用完即删临时文件。

### 三个「实现要点」的取材（都是项目里真实的架构决策，不是套话）
1. **盘面是烘焙的**：`textureGenerator.ts` 在 Canvas 画 2048² 贴图；换视角时重烘焙，
   用 `source-atop` 压暗非目标环（用 `destination-out` 会挖透明、透出盘底棕色）。
2. **盘面与铜环解耦**：铜环几何边界（2.22/3.12/4.16…）与贴图内容边界
   （1.76/2.50/3.62…）对不齐，早期让铜环承载贴图会把内容环切断。
3. **音效全合成**：`find src public -name "*.mp3|*.wav|*.ogg|*.m4a"` 为空 → 无音频文件，
   颂钵/铜铃由振荡器 + 卷积混响实时生成。

### 竞品扫描带来的关键差异化（意外收获）
搜「3D风水罗盘」出来的全是安卓工具类 App（开运风水罗盘 / 3d风水罗盘 等，
2026-09 至 10 仍有更新），共性：
靠**手机磁力传感器**测方位，卖点是看房、装修、吉凶解析，要下载安装，盘面是贴图。

→ 本项目全部相反：不测方位、纯文化展示、浏览器即开、盘面是程序化烘焙的真 3D 几何。
**结论：文案核心立足点是「不跟它们抢工具赛道，走器物/作品赛道」**，
开头第一句就是「不是风水测算 App，也不是手机指南针」制造反差。
